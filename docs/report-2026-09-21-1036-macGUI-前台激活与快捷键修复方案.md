# macGUI 前台激活与快捷键体系修复方案

> 针对「Dock 无图标 / 菜单栏不归属本 App / 快捷键全部失效」三个
> 现象做实证诊断，给出已实测的最小修复与根治方案，并补齐一套
> 完整快捷键体系。状态：✅ 已执行（2026-09-21，方案 A）

## 1. 现象与实测证据

| 现象 | 实测（`lsappinfo`，本轮运行 `mac-gui/.build/debug/AVDC`） |
|------|--------------------------------------------------------|
| Dock 无图标 | `type="BackgroundOnly"`、`bundleID=[ NULL ]` |
| 菜单栏仍显示别的 App | 启动后 `lsappinfo front` 的 ASN 未变，仍是启动前的 App |
| 快捷键全部失效 | 菜单栏不归属本进程 → NSMenu 的 `keyEquivalent` 不会派发到本进程 |
| 登记路径异常 | `bundle path` 指向 `mac-gui/.build/out/Products/Debug/AVDC` |

关键结论：**三个现象同一个根因**，不是三处独立 bug。

## 2. 根因：无 bundle 导致 LaunchServices 按 BackgroundOnly 登记

无 `.app` bundle（方案决策 4）时，LaunchServices 只能按可执行文件
登记进程，type 落到 `BackgroundOnly`：

1. BackgroundOnly 进程不生成 Dock 项
2. BackgroundOnly 进程不接管菜单栏（系统仍显示上一个前台 App）
3. macOS 的菜单键等同只在「本进程拥有菜单栏且处于激活态」时派发
   → 我们写在 `Commands` 里的 ⌘R/⌘./⌘1–⌘3/⌘O/⌘E 全部失效，
   连带系统自带的 Edit 菜单项（⌘C/⌘V/⌘A/⌘Z）也失效

> 说明：这不是 SwiftUI 的锅。SwiftUI 已经把完整菜单树建好了
> （见 §5 实测转储），只是进程没有资格把它显示出来。

## 3. 方案 A：最小修复（1 个文件，已实测生效）

```swift
// Sources/AVDCApp/AppDelegate.swift（新增）
final class AppDelegate: NSObject, NSApplicationDelegate {
    func applicationDidFinishLaunching(_ n: Notification) {
        // 无 bundle → LS 登记为 BackgroundOnly，显式改回前台
        NSApplication.shared.setActivationPolicy(.regular)
        NSApplication.shared.activate()
    }
    // 单窗口工具：关掉主窗口即退出
    func applicationShouldTerminateAfterLastWindowClosed(
        _ sender: NSApplication) -> Bool { true }
}

// Sources/AVDCApp/AVDCApp.swift
@NSApplicationDelegateAdaptor(AppDelegate.self) private var appDelegate
```

实测结果（同一台机器、同一构建方式）：

| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| lsappinfo type | `BackgroundOnly` | `Foreground` |
| 前台 App | 仍是别的 App | 本 App（`lsappinfo list` 标 `(in front)`） |
| 菜单栏归属 | 无 | AVDC（菜单转储正常，见 §5） |
| Dock 图标 | 无 | 出现（通用可执行图标） |
| 菜单快捷键 | 不派发 | 可派发（待人工按键确认） |

残留限制（无 bundle 的固有代价）：

- Dock 图标为系统通用图标，不是 AVDC 图标
- 右键「固定到 Dock」记录的是 `.build/debug/AVDC` 路径，
  `swift build` 清理重建后可能失效
- 不能双击启动、不能被「打开方式」关联、没有 bundle id

## 4. 方案 B：根治（极简 `.app`，需回看决策 4）

只做「身份」打包，不做签名/公证（本地自用）：

```
AVDC.app/Contents/
├── Info.plist          # CFBundleExecutable/Name/Identifier/PackageType=APPL
├── MacOS/AVDCApp       # swift build -c release 产物
└── Resources/AppIcon.icns   # 可选，Icon Composer 生成
```

- 具备 `CFBundlePackageType=APPL` 且不含 `LSUIElement` → LaunchServices
  天然按前台 App 登记，§3 的 AppDelegate 补丁可省略（留着也无害）
- 收益：Dock 图标可控、可固定、可双击启动；About 面板可读 Info.plist
- 成本：`scripts/make-bundle.sh`（约 30 行）+ Bridge 定位改造

⚠️ Bridge 定位必须同步解决：`findProjectRoot()`（`Bridge.swift:89`）
靠 cwd 向上找 `cli/cli.py`，Finder 双击启动时 cwd 为 `/` →
需增加「环境变量 `AVDC_PROJECT_ROOT` → 设置项 → 默认路径」回退链。

## 5. 快捷键体系现状（实测菜单转储）

启动后 dump `NSApp.mainMenu`（本轮实测，已把 App 激活修好再转储）：

| 菜单 | 已有项（含快捷键） | 缺口 |
|------|-----------------|------|
| AVDC | 关于 AVDC；Settings… ⌘,；Services；Hide/Hide Others ⌘H/⌘⌥H；Quit ⌘Q | 无 |
| File | 选择影片目录 ⌘O；导出日志 ⌘E；Close ⌘W；Close All ⌘⌥W | 无（New 已按 HIG 移除） |
| Edit | Undo ⌘Z / Redo ⌘⇧Z / Cut ⌘X / Copy ⌘C / Paste ⌘V / Select All ⌘A / AutoFill / Dictation / Emoji | 无（系统自带，激活后即可用） |
| View | 主页 ⌘1、工具 ⌘2、日志 ⌘3 | **缺「进入全屏」⌃⌘F** |
| 处理 | 开始处理 ⌘R；停止 ⌘. | 无 |
| Window | Minimize ⌘M；Zoom；Bring All to Front | 无（全屏按 HIG 应放 View） |
| Help | AVDC Help ⌘?；Toggle Sidebar ⌘⌥S | 「AVDC Help」无帮助书点了没反应；**⌘⌥S 被 SwiftUI 放到 Help 末尾**（应属 View） |

补齐要点（均已在临时副本验证位置）：

- ⌃⌘F 全屏：`CommandGroup(after: .toolbar)` + `NSApp.keyWindow?
  .toggleFullScreen(nil)` → 实测落在 **View** 菜单（用
  `after: .windowSize` 会落进 Window，不符 HIG）
- 页面切换沿用 `CommandGroup(after: .toolbar)`，实测落 View ✔
- ⌘⌥S 归位：需把 `NavigationSplitViewVisibility` 状态放模型
  （CLT 无 `@State`），再用 `replacing: .sidebar` 自建该项
- Help 菜单：`AVDC Help` 无帮助书，建议替换为「打开项目文档」
  或忽略（不影响功能）

## 6. 快捷键实现规则（固化到 AGENTS.md 常见坑）

1. **唯一注册点**：`keyEquivalent` 只写在 `Commands.swift`；
   视图按钮只写 `.help("…（⌘R）")` 标注，不重复注册同一键
2. **置灰不隐藏**：条件不满足用 `.disabled`，保持菜单结构稳定
3. **新增键先查转储**：新增前确认不与系统项冲突（⌘W/⌘M/⌘Q/⌘Z/
   ⌘C/⌘V/⌘A/⌘H/⌘, 已被系统或我们占用）
4. **页面级动作**：与页面强相关的动作放页面菜单（处理）或
   View（切页），不进 File
5. **可选补充**：⌘F 聚焦搜索框（Log/Settings 页）、⌘D 复制当前
   选中项、工具页动作（待实现后补）
