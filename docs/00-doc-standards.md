# 文档写作标准

> 本文件是 AVDC 项目所有文档的写作规范。新建或修改文档前必须阅读。

## 1. 文件组织

### 1.1 一个文档一个主题

每个 `.md` 文件只聚焦一个主题，禁止在同一文件中混杂不相关的内容。

### 1.2 大小上限：10 KB

单个文件不超过 10 KB。超过时必须拆分为多个文件。

### 1.3 零重叠原则

同一信息只在一处完整描述，其他地方用链接引用。
如果发现两份文档在说同一件事，应该合并或指向其中一个。

### 1.4 Overview 文件

每个子目录必须有一个 overview 文件，命名以 `00-` 开头。
Overview 职责：

- 简述本目录涵盖的内容范围
- 列出所有子文档，每个文档用一句话摘要
- 如有 design / trap 分类，在对应条目注明文档编号

顶层 `docs/` 不需要 overview（本文件即承担此职责）。

## 2. 命名规范

### 2.1 顺序编号

文档以数字前缀排序，确保阅读顺序明确。

### 2.2 分类前缀

| 前缀 | 含义 | 用途 |
|------|------|------|
| `00-` | overview | 目录概览/索引 |
| `01-`, `02-`, … | 顺序文档 | 常规主题（无分类需求时） |
| `d01-`, `d02-`, … | design | 程序设计、架构、实现细节 |
| `t01-`, `t02-`, … | trap | 踩坑记录、问题与解决方案 |

**规则**：同一目录下，要么全部用数字编号（`01-`, `02-`），要么使用 d/t 分类编号。不混用。

### 2.3 文件名示例

```
docs/
├── 00-doc-standards.md           ← 文档标准（本文件）
├── 01-project-overview.md
├── 02-architecture.md
├── core/
│   ├── 00-overview.md
│   ├── 01-requirements.md
│   └── 02-scraping-flow.md
└── pyside6gui/
    ├── 00-overview.md
    ├── d01-architecture.md        ← 设计类
    ├── d02-theme-system.md
    ├── t01-dynamic-property.md    ← 踩坑类
    └── ...
```

## 3. 内容结构

### 3.1 标题

一级标题 `#` 只有一个，即文档主题名。

### 3.2 摘要行

标题下方用 `>` blockquote 写一句话概括文档内容，便于快速浏览。

### 3.3 正文层级

最多用到三级标题 `###`，避免过深嵌套。

### 3.4 代码示例

- 用实际代码，不用伪代码（除非在解释抽象概念）
- 标注来源文件路径（注释或表格）
- 错误示例标 ❌，正确示例标 ✅

### 3.5 表格 vs 列表

- 对比、属性速查、配置项 → 用表格
- 步骤、枚举、概念列举 → 用列表

### 3.6 Overview 中的索引格式

Overview 中对每个子文档用一句话总结，格式：

```markdown
| 编号 | 文档 | 类型 | 一句话摘要 |
|------|------|------|-----------|
| d01 | [架构设计](d01-architecture.md) | design | 整体架构与数据流向 |
| d02 | [主题系统](d02-theme-system.md) | design | 颜色/间距/字号常量参考 |
| t01 | [动态属性陷阱](t01-dynamic-property.md) | trap | Qt 动态 Property 注册失败的解法 |
```

## 4. 写作风格

- **语言**：中文为主，技术术语/代码/命令保留英文
- **语气**：直接、简洁，不写废话
- **链接**：跨文档用相对路径引用，不复制内容
